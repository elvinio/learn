02

Message structure

Header: version, routing, and session fields. Body: order fields. Trailer: checksum.

Tags and the separator

55=AAPL: tag 55 is Symbol; its value is AAPL. SOH separates fields. SOH means Start of Heading: the ASCII control character with decimal value 1 (hex 0x01), not the printed digit 1.

SOH is displayed as |. The wire message has no added spaces or line breaks.

Field order

First fields: 8, 9, 35, in that order. Remaining header fields precede the body.

Last field: 10, followed by SOH.

CheckSum adds bytes

the value of tag 10

Sum byte values from 8= through the SOH before 10=. Take the remainder after division by 256. Format as three digits.

Checksum byte values: SOH = 1; | = 124. Calculate with SOH. CheckSum detects some transmission errors; it provides no authentication.

A replace request supplies the full desired order details, not just changed fields. Already filled trades remain unchanged.

Replace responses

  • Accepted: Execution Report 35=8, 150=5. Later replace or cancel requests target 41=ORDER-002.
  • Pending: Execution Report 35=8, 150=E. The replacement is not yet accepted.
  • Rejected: Order Cancel Reject 35=9, 434=2. ORDER-002 does not become active; later requests still target ORDER-001.

The order may fill while replacement is pending. This example has no fills before replacement.

Tag 41 targets the order. Tag 56 identifies the receiving system. Tag 37 is the broker’s order ID; include it if required by the broker.

Cancel responses

  • Accepted: Execution Report 35=8, 150=4, 39=4. The remaining quantity is canceled.
  • Pending: Execution Report 35=8, 150=6, 39=6. Cancellation is not yet complete.
  • Rejected: Order Cancel Reject 35=9, 434=1. Cancellation failed; check the reported order status.

Orders may fill before cancellation completes. Canceling does not reverse prior fills.

Original-order path: new → cancel. After-replace path: new → accepted replace → cancel. Outgoing sequence numbers assume no intervening client messages. Session setup requires Logon, Heartbeat, and Logout.

Cancel and replace rejection

Order Cancel Reject uses 35=9. 434=1 rejects a cancel; 434=2 rejects a replace. Tag 102 gives the reason; tag 39 reports the order’s current status. Rejecting a request does not itself reject the order.

A session Reject (35=3) concerns a message-level error, such as a missing required tag. It is separate from order rejection.
